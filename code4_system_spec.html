code4（2G_Tcode4）模組系統規格文件

這不是 code1/code2/code3 的第四層延伸——是另一個獨立子系統 檔名雖然叫「code4」，但實際檔名是 2G_Tcode4*.asp，資料表是 TB_ALEX_RepairCode4_200601（前綴 TB_ALEX_，不是前面三個模組用的 TB_GD_）， 使用的資料庫連線是 conn3（前三個模組用 conn／conn0）。這是「2G 票務中心」系統的選單設定模組，商業意義是「地區管理」， 與 code1/code2/code3（項目/服務/品牌管理）用的是同一套 Code1/Code2/Code3 資料表做關聯查詢，但賦予了不同的業務標籤（見第4章）。

文件目的 本文件整理 8 個 2G_Tcode4*.asp 檔案，供 AI／工程師改寫成其他程式語言時參考。內容包含資料模型、頁面流程、商業規則、已知缺陷。

1. 模組概觀

此模組中文名稱為「地區管理」，是「2G 票務中心」選單設定系統的第四層節點。完整的選單層級（此系統自建，與 code1/2/3 的 1G 資料共用但重新命名）：

TB_ALEX_RepairCode1_200501（業態，沿用 code1 模組的 Code1 表結構） └─ TB_ALEX_RepairCode2_200501（品牌，沿用 code2 模組的 Code2 表結構） └─ TB_ALEX_RepairCode3_200501（票務，沿用 code3 模組的 Code3 表結構） └─ TB_ALEX_RepairCode4_200601（地區） ← 本模組管理的對象 └─ TB_ALEX_RepairCode5_200601（類型，下一個模組 code5）

每一筆地區代碼（Code4）除了照抄 code1/2/3 那套「編號＋名稱＋啟用狀態＋圖片＋重複檢查」的舊邏輯（本文稱為「1G 欄位」）， 還新增了一整套用於行動/網頁售票介面選單按鈕外觀與販售期間設定的欄位（本文稱為「2G 欄位」）：排序、按鈕主副標題、按鈕小圖、LOGO、 服務指引文字、頁面標題、是否顯示步驟進度條與其樣式、以及「開始/停止預售時間」。這兩組欄位在編輯頁面上是否可編輯，各自由不同的旗標獨立控制（見第4章）。

狀態不再是二元（啟用/停用），而是三態：Use_flag = 0（啟用）/ 1（停用）/ 2（待上架），並有專屬的「2G_Tcode4ready.asp」頁面負責在 啟用與待上架之間切換（停用仍走既有的 mod_stop 流程）。這證實了 code2/code3 模組規格文件中提到「畫面上出現但未確認用途」的「2=待上架」選項， 在 2G 系統裡是真實且完整實作的狀態。

4. 架構重點

雙資料庫、三連線
本模組固定用 conn3 操作所有 TB_ALEX_* 表；但寫操作記錄時用另一條連線 conn 寫入 TB_GD_UserClick_Log_200507（1G 主庫的表）。同一支程式同時操作兩個資料庫，改寫時要確保有等價的雙連線/雙資料源設計，或評估是否合併。
1G欄位 vs 2G欄位
「1G欄位」＝ Item_4、Item4_name、Item4_pic、Use_flag、預售起訖時間——是從 code1/2/3 模組沿用下來的舊欄位語意。
「2G欄位」＝ Sort、Code4_Name、SubTitle、Code4_Pic、ShowCode4_Pic、ShowHot、Logo_Pic、ShowLogo_Pic、MapText、ShowMapText、Title、IsStep、StepMode——全部是本模組新增、用於選單按鈕外觀與下一頁UI設定的欄位。
在編輯頁（2G_Tcode4mod_temp.asp），兩組欄位是否可編輯由兩個獨立旗標控制：ReadOnly_1GField（當 mod=2 停用模式，或 目前 Use_flag<>"1"，即目前不是「停用中」狀態，1G欄位就唯讀）；ReadOnly_2GField（只有 mod=2 停用模式才唯讀）。也就是說：只有目前狀態是「停用中」時，才能編輯1G欄位（編號/名稱/圖片/預售期間）；但2G欄位（外觀設定）不論目前狀態是啟用/停用/待上架，只要不是進入「停用」這個動作本身，就永遠可以編輯。
三態狀態機
Use_flag：0=啟用、1=停用、2=待上架。三個狀態之間的轉換路徑：列表頁【修改】永遠可點進 mod_temp.asp（不論目前狀態）；【停用】只在目前啟用中(0)時出現，走 mod_stop.asp 把狀態設為1；從 mod_temp.asp 或其【待上架】按鈕可進入 ready.asp，可把狀態設為 0 或 2（該頁 Use_flag=1 選項被 disabled，不能從這裡設回停用）。
雙導覽路徑（flag／Curr_Dir）
列表頁用單一變數 Curr_Dir 統一處理路徑前綴（flag="0" 時為空字串，即用相對路徑；否則為 Session("folder")），所有連結一致套用此變數。這比 code3.asp 用一堆重複的 if/else 區塊乾淨，但本質上是同一種「雙入口」設計，改寫前仍需確認兩種入口是否都還有真實流量。
99互斥規則沿用
與 code2/code3 模組相同的「編號99與其他啟用中代碼互斥」規則，在新增與編輯都各自實作一次。

5. 頁面流程圖

2G_Tcode4.asp（列表，四層連動查詢：業態→品牌→票務→[本頁地區]） │ ├─[新增代碼] ──► 2G_Tcode4add.asp ──submit──► 2G_Tcode4add_db.asp │ ├─99互斥檢查失敗 → alert → 導回 │ └─成功 → INSERT(1G+2G全部欄位) → 導回 │ ├─[修改]（列表頁每列都會顯示，不論目前狀態） │ └────► 2G_Tcode4mod_temp.asp?mod=1 │ │ 依 Use_flag 是否為"1"(停用中) 決定 1G 欄位可否編輯；2G 欄位固定可編輯 │ │ submit │ ▼ │ 2G_Tcode4mod.asp ──視 use_flag_old="1" 才更新1G欄位(含99互斥檢查)──► 無條件更新2G欄位 │ ──► 寫入 TB_GD_UserClick_Log_200507（conn） │ ──► 導回 │ ├─[停用]（僅目前 Use_flag=0 時顯示） │ └────► 2G_Tcode4mod_temp.asp?mod=2&Use_flag=1 （全唯讀） │ │ submit │ ▼ │ 2G_Tcode4mod_stop.asp ──► 檢查下層類型代碼(Code5)是否有啟用/待上架中的 │ ├─是 → alert(禁止停用) → 導回 │ └─否 → UPDATE Use_flag='1' → 寫記錄 → 導回 │ └─[待上架]（mod_temp.asp 內按鈕，任何狀態都可點） └────► 2G_Tcode4ready.asp ──submit──► 2G_Tcode4ready_db.asp ──► UPDATE 預售期間+Use_flag(0或2) ──► 寫記錄 ──► 導回 （另有【暫停訊息】按鈕連到資料夾外的 Tcode4stopmsg.asp，行為未知，見第3章）

insert into TB_GD_UserClick_Log_200507
  (uid,username,companyid,webname,webid,funname,funid,subname,subid,ip_address,goods_name)
values
  (<session aid>, <session cname>, <session companyid>, '產品管理', <wid>,

處理器 7.3 2G_Tcode4add_db.asp — 新增寫入

與code2add_db.asp相同模式的99互斥規則：先查此票務(code1+code2+code3)下是否已有啟用中的Item_4=99 → 若有拒絕；若欲新增99則查是否已有任何啟用中地區 → 若有拒絕；否則查是否有相同Item_4且啟用中 → 若有拒絕
SQL(INSERT)

頁面 7.4 2G_Tcode4mod_temp.asp — 編輯／停用中繼表單

資料讀取
五表join確認地區存在且父鏈(Code1/Code2)啟用中；查無資料時本檔案有正確呼叫 response.End（與code2/code3模組的D2-08類缺陷不同，本檔案沒有這個問題）
ReadOnly判斷
ReadOnly_1GField：mod="2" 或 Use_flag<>"1" 時為真（即只有「目前狀態=停用中」且是編輯模式時，1G欄位才可編輯）；ReadOnly_2GField：僅 mod="2"（停用模式）時為真

依 mod 指向 2G_Tcode4mod.asp 或 2G_Tcode4mod_stop.asp
額外入口
【待上架】→ 2G_Tcode4ready.asp；【暫停訊息】→ 資料夾外的 Tcode4stopmsg.asp（見第3章）

處理器 7.5 2G_Tcode4mod.asp — 編輯寫入

條件式更新1G欄位
只有 use_flag_old="1"（即編輯前的狀態是停用中）才會進入這個區塊去檢查與更新Item_4/Item4_name/圖片/預售期間/Use_flag。
程式缺陷（D4-02，重要）：99互斥檢查被自我註解掉一半
當 item_4="99" 時，程式組出 sqlsel2 查詢「該票務下是否還有其他啟用中的地區」，並執行了查詢取得 rsring2，但緊接著判斷分支 if not rsring2.eof then ... alert(...) ... response.End ... else ... end if 整段的 if/else 判斷本身連同alert都被註解掉了，只留下中間原本該屬於 else 分支的 UPDATE 陳述式沒有被註解、永遠會執行。 換句話說：「修改為99時若已有其他啟用中地區應該擋下來」這條規則目前完全不會被執行，跟 code2/code3 模組的 D2-06、D3-05 是類似性質但更明確的「防呆邏輯被停用」案例。
2G欄位
完全無條件更新（不受use_flag_old影響），13個欄位一次UPDATE
稽核
寫入 TB_GD_UserClick_Log_200507（見6.3節），此為真正執行的寫入

處理器 7.6 2G_Tcode4mod_stop.asp — 停用寫入

前置檢查

8. 商業規則彙整

  1. 父鏈需啟用（部分）：列表與編輯頁的查詢條件要求Code1、Code2啟用中；但沒有一致地檢查Code3(票務)本身的use_flag（見D4-01），與code2/code3模組「一路檢查到底」的作法不同。
  2. 三態狀態機：0=啟用/1=停用/2=待上架；停用只能透過mod_stop設定，啟用/待上架透過ready_db設定，兩條路徑互不重疊。
  3. 1G欄位編輯權限綁定狀態：只有目前狀態為「停用中」時才能編輯地區編號/名稱/圖片/預售期間；2G欄位（外觀設定）任何非停用操作的情境下都可編輯。
  4. 2G欄位無條件更新：不論1G欄位是否符合編輯權限，2G欄位一定會被更新（除非該次請求走的是mod_stop或ready，那兩支不觸碰2G欄位）。
  5. 99互斥規則（新增有效，編輯已失效）：新增時99與其他啟用中地區互斥的檢查正常運作；編輯時同等的檢查因D4-02缺陷已經失效。
  6. 停用前檢查下層：停用地區前必須確認Code5(類型)沒有非停用(<>1)的記錄。
  7. 操作稽核：編輯、停用、狀態調整都會在1G主庫寫入一筆點擊記錄（與code1/2/3模組「log被註解掉」不同，這裡是真的會寫入）。

9. 已知問題／技術債

編號問題影響出現位置
D4-01列表與部分頁面的join條件檢查了Code1、Code2的use_flag，但沒有檢查Code3(票務)本身是否啟用票務本身被停用後，其下地區可能仍會出現在列表/可編輯，與其他層級「一路檢查到底」的慣例不一致2G_Tcode4.asp、2G_Tcode4mod_temp.asp等的join條件
D4-022G_Tcode4mod.asp 修改為編號99時的「其他啟用中地區」檢查，其判斷分支(if/else + alert)被整段註解，只留下UPDATE語句必定執行99互斥規則在編輯情境下完全失效2G_Tcode4mod.asp 第79-101行
D4-032G_Tcode4mod_stop.asp 的拒絕停用訊息文字前後不一致（提到「類型管理」又提到「此品牌的商品」）純文案問題，不影響邏輯，但會讓使用者困惑2G_Tcode4mod_stop.asp 第20行
D4-042G_Tcode4ready.asp 查無資料時只alert沒有response.End，後續繼續讀取空Recordset欄位會在伺服器端出錯，而非停留在友善警告訊息（與code2/code3模組的D2-08同類）2G_Tcode4ready.asp 第46-53行
D4-05mod_status 變數在 2G_Tcode4ready.asp 中從未賦值卻被輸出到畫面畫面標題與按鈕文字會出現空白（如「地區管理<>」）2G_Tcode4ready.asp 第149、340行
D4-06SQL字串串接（Injection風險）、err<>0錯誤處理形同虛設——與code1/2/3模組相同的通用缺陷同前述模組幾乎所有檔案
D4-07雙資料庫寫入（conn3寫主檔、conn寫log）沒有交易(transaction)包裹，若log寫入失敗，主檔更新已經送出，兩者可能不一致資料一致性風險（雖然影響僅限稽核記錄本身，不影響業務資料）2G_Tcode4mod.asp、mod_stop.asp、ready_db.asp
D4-08func_2G_Common.asp、func_HTML.asp、func_2G_Ticket.asp、2G_Common.js 四個共用函式庫的實作內容完全未提供，本文件中大量欄位的驗證/轉換/預設值邏輯（ConvUni2ASC、FixFlagValue、GetChecked、ValueIs99、checknull_2G等）都是黑盒改寫時這些函式的真實邏輯必須另外取得原始碼才能百分之百還原行為；本文件只能描述「看得到的呼叫方式」全模組
D4-09暫停訊息功能實際連到資料夾外、命名不含2G_前綴的Tcode4stopmsg.asp，行為完全未知本文件無法涵蓋暫停公告這部分的行為，改寫前需另外取得該檔案2G_Tcode4mod_temp.asp 的暫停訊息按鈕

11. 改寫建議

  • 優先取得四個共用函式庫的原始碼（func_2G_Common.asp、func_HTML.asp、func_2G_Ticket.asp、2G_Common.js），否則本模組的欄位驗證/預設值/轉碼邏輯無法百分之百還原。
  • 把1G欄位／2G欄位的可編輯權限規則顯式建模為一個狀態機函式（輸入目前Use_flag與操作模式，輸出兩個布林值），而不是像原始碼一樣散落在畫面渲染邏輯裡。
  • 修復D4-02後再決定要不要保留：編輯時的99互斥檢查目前形同虛設，建議先跟需求方確認新系統是否要真的攔截這個情境。
  • 合併雙資料庫寫入為單一交易，或至少讓稽核記錄的失敗不影響主資料的成功判斷（目前程式碼即使log寫入失敗，使用者仍會看到「修改成功」，因為err判斷邏輯本身就不可靠，見D4-06）。
  • 比照code1/2/3模組的REST風格，設計 GET/PUT /api/groups/{groupId}/tickets/{code3}/regions/{code4}、POST .../regions/{code4}/ready、POST .../regions/{code4}/deactivate 等端點，並把「開始/停止預售時間」的+1天儲存慣例封裝在服務層內部。
