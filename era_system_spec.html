1. 模組概觀

ERA（Enterprise Retail Arrangement，推測縮寫）是「2G 票務中心」後台的商品管理子系統， 負責維護票券商品主資料（TB_ALEX_MainTicket_200604）。 每筆商品掛載於五層分類碼樹（code1→code2→code3→code4→code5）之下， 並與廠商（cid）、廠商連結（comid）相關聯。

⚠ 重要：code5=90 雙分支 商品分兩種形態：
• 一般商品（item_5 ≠ 90）：有節目名稱、起訖站、贊助商、備註欄位等完整欄位。
• 特殊商品（item_5 = 90，且 actionid = "0610"）：欄位大幅精簡，僅有 programid、票面格式、預售日期等核心欄位，無節目名稱與交通相關欄位。
整個新增/編輯/顯示頁面都用 if item_5="90" 判斷分支，改寫時必須完整保留此邏輯。

6. 商業規則

6.1 code5=90 特殊分支（actionid="0610"）

當 item_5="90" 且 actionid="0610" 時，商品為「精簡版」：

  • 新增/編輯 SQL 使用精簡欄位集（不含 programname, begin_busid, end_busid, via_busid, programkindid, sponsorname, sponsorcontent_1~3, specialnote, ticket_num, t_note1~6, if_batch 欄位）
  • UPDATE 語句同樣精簡，只更新 programid/startpresale/stoppresale/Slotting_Date/ticket_format/receipt_format/cid/comid 及 2G 展示欄位
  • 非批次查重邏輯以 cid 取代 comid 作為查重維度

6.2 批次 / 非批次 (if_batch)

if_batch=1（批次）：直接 INSERT，不做場次唯一性檢查。適用於大量批次匯入情境。
if_batch=0（非批次）：INSERT 前先以 code1+code2+code3+code4+code5+comid（或 cid）查詢是否已存在非批次商品，若有則 alert 警告並 history.go(-1)，阻止重複建立。

6.3 programid 重複檢查

  • 條件：use_flag=0（啟用）AND len(programid)=11 AND（cid = cid_52 OR cid = cid_9Q）
  • 呼叫 fnGetDuplicateProgramID(conn3, pdid, programid)（定義在 func_2G_Ticket.asp）
  • 新增時 pdid 傳 -1（排除自身用；新增無自身）
  • 重複則 alert 提示並 history.go(-1)
  • ⚠ JS 前端也有檢查，但 Server 端仍有再驗，避免繞過 JS

6.4 預售日期 ±1 天轉換

⚠ 容易出錯的隱性轉換
資料庫存的 stoppresaledate（及 startpresaledate）比 UI 顯示值多 1 天：
• 讀取時（Mod/Show）：stoppresaledate = dateadd("d",-1, rs("stoppresaledate")) 顯示給使用者
• 寫入時（Add_db/Mod_db）：stoppresaledate = dateadd("d",1, Request("stoppresaledate")) 存入 DB
改寫時必須保留此邏輯，否則每次修改都會使日期偏移。

6.5 pcode_in 流水號規則

pcodein_num = (SELECT pcodein_num FROM TB_ALEX_PcodeIn_Serial_200603 WHERE actionid=?) + 1
pcode_in = actionid + LPAD(pcodein_num, 10, '0')   -- 共補到 10 位
UPDATE TB_ALEX_PcodeIn_Serial_200603 SET pcodein_num = pcodein_num WHERE actionid=?
INSERT INTO TB_ALEX_RefundTicket_201106 (pcode_in) VALUES (?)
⚠ 競態條件（Race Condition）：原始碼無交易（Transaction）保護，高並發下可能產生重複 pcode_in。改寫時應使用資料庫交易或 SEQUENCE。

6.7 場次狀態 (U_Flag) — 列表操作按鈕決策

查詢 TB_ALEX_Session_200604（場次表）該商品是否有 use_flag IN (0,2,3) 的場次：

U_Flag 值說明列表顯示按鈕
1（eof = 無場次）已下架/無場次「修改資料」→ Mod_ERA_Ticket
0（有 use_flag=0 場次，上架中）上架中「查看資料」+ 「查看詳情」→ Show_ERA_Ticket
2待上架同上
3待確認同上
4待設定同上
注意：U_Flag 值輸出到畫面用中文（「上架中」等），但按鈕判斷只看 U_Flag="1"；其他值一律走唯讀流程。

6.8 2G 展示欄位（IsStep / StepMode 特殊規則）

  • IsStep：0 表示無步驟，1 表示有步驟；透過 FixFlagValue(Request("IsStep"), "0", "1") 處理，確保只有 "0"/"1"
  • StepMode：僅在 IsStep=1 時有意義；使用 FixStepModeValue 函式，當 IsStep=0 時強制 StepMode 為某固定值（推測為 "0" 或空白）；StepMode 預設值 "1" 時同時接受 StepMode="0"（允許"無"勾選）
  • 圖片欄位（Item_Pic / Logo_Pic）：若對應的 ShowItem_Pic / ShowLogo_Pic 為 "0"，則用 ClearPicIfUnChecked 清空圖片路徑（防止存入未顯示的圖）

7.3 2G_Add_ERA_Ticket.asp 頁面

用途：新增商品表單。POST action → 2G_Add_ERA_db.asp。

關鍵邏輯

  • code5 onChange reload 本頁，帶 code1~5 及 cid 等參數，頁面重新載入後依 item_5 決定顯示的欄位群組。
  • code5 選定後：查 TB_ALEX_RepairCode5_200601 JOIN TB_ALEX_RepairCode1_200501 取得 item_5 及 actionid。

9. 改寫建議

  • 資料存取：改用 Parameterized Query（Dapper / EF Core），根除 SQL Injection。
  • 序號生成：使用 DB SEQUENCE 或 BEGIN TRAN + SELECT FOR UPDATE，確保 pcode_in 原子性。
  • 商品形態：以明確的 ProductType enum 取代 item_5="90" 隱性判斷；可拆成兩種 DTO/Entity。
  • 日期轉換：將 ±1 天邏輯封裝成 domain layer 轉換（ToDbStopDate / FromDbStopDate），避免散落各頁面。
  • 下架目標表：確認 ERATICKET 與 MainTicket 的關係，統一下架邏輯。
  • 代碼階層：code1~5 五層聯動可用 parent-child 遞迴查詢取代五張 JOIN，並在前端做 AJAX 懶載入。
  • 前後端驗證：programid 重複、if_batch=0 場次唯一性，均應整合為後端 Validator，前端做輔助提示。
  • 廠商跨庫：GD_SALES_BARK 跨庫查詢建議改為 API 呼叫或 View，降低資料庫耦合。
